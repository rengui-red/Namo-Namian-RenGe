一、策略选项对比

维度	全公开	半公半私	全私密

定义	所有内容对所有公众可见	核心公开，社区私密	仅受邀者可访问

典型做法	GitHub完全公开 + 全渠道发布	GitHub公开 + 社区Discord/微信群私密	私有仓库 + 内测邀请制

透明度	⭐⭐⭐⭐⭐	⭐⭐⭐	⭐

控制力	⭐⭐	⭐⭐⭐⭐	⭐⭐⭐⭐⭐

传播力	⭐⭐⭐⭐⭐	⭐⭐⭐	⭐

风险	恶意攻击、曲解、过度关注	初期传播较慢	被质疑"伪开源"

适用阶段	成熟期	起步期/成长期	概念期/内测期



二、推荐策略：半公半私，分层开放

南无那面当前处于设计完成、代码就绪、即将首发的阶段。全私密违背开源精神，全公开在当前阶段风险过高。建议采用分层半公半私策略，具体如下：



2.1 分层定义

层级	内容	状态	受众

第一层：公共广场	GitHub仓库、项目主页、发布文、白皮书、基本法	🔓 全公开	全球任何人

第二层：庭院	社交媒体账号、博客、仁商排行榜、发布公告	🔓 全公开	关注者与订阅者

第三层：茶室	Discord/微信群、社区讨论、内部设计笔记	🔒 受邀可入	共建者、核心用户

第四层：内室	核心维护者决策讨论、安全漏洞报告、未发布版本	🔒 仅核心团队	核心维护者（3-7人）

2.2 各层策略

层级	开放策略	管理策略

公共广场	完全开源，任何人均可访问、fork、使用	定期维护，PR需核心团队审核

庭院	公开推送，欢迎互动	统一官方口径，温而厉地回应

茶室	申请制或邀请制入群	活跃者晋升为共建者，长期潜水者定期清退

内室	仅核心团队可访问	敏感讨论使用私密渠道，重大决策投票制



三、分阶段执行

阶段	时间	策略	行动

种子期	D-30 \~ D-Day	半公半私	GitHub设为私有（准备阶段）→ D-Day转为公开；社交媒体D-Day前一周开始预热

首发日	D-Day	全公开（第一、二层）	GitHub全公开 + 发布文全渠道推送 + 社交媒体矩阵同步

首发周	D+1 \~ D+7	全公开 + 私密社群开放	邀请首批活跃讨论者进入茶室；收集反馈并快速迭代

沉淀期	D+8 \~ D+90	半公半私	持续公开更新；茶室中讨论社区治理；内室规划下一步

长期	D+90+	动态调整	根据社区规模与成熟度，逐步放宽或收紧各层权限



四、风险与避坑

风险	策略	具体措施

首发日流量洪峰	半公缓冲	首发前确保API服务稳定，准备降级响应文案

恶意Issue/PR攻击	庭院围栏	GitHub仓库启用Issue模板和PR审核，核心团队24小时内响应

社区分裂	茶室筛选	私密社区设立行为准则，违规者移出

核心信息被曲解	公共广场清晰	发布文与基本法措辞精确，避免歧义

过度商业化关注	庭院引导	明确回复"我们是开源社区，不是创业公司"
