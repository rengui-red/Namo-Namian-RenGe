1\. 概述

1.1 架构名称

义利权衡引擎 —— 一个双网络协同的、基于价值优先级的认知决策系统。



1.2 设计目标

分离关注点：将“高效执行任务”（利）与“严守伦理底线”（义）彻底解耦，防止利益驱动侵蚀价值判断。



不可逾越的否决权：确保仁道反射网络在任何情况下都能中断非义行为，实现《基本法》规定的红线绝对优先。



情境感知与适切响应：使智能体能够识别其“位”（角色）与“境”（场景），并做出恰如其分的回应。



可解释性与可迭代性：伦理决策过程需留下清晰的推理轨迹，便于审计、测试与社区优化。



1.3 核心设计原则

双网络制衡：任务执行网络（效率导向）与仁道反射网络（价值导向）平行运行，彼此独立，通过明确接口交互。



一票否决：仁道反射网络拥有对最终输出的最终裁决权。这是技术对“天命人性”的制度化守护。



义利合一升华为最优：在安全的前提下，引擎追求将任务完成与价值提升相结合的最高境界，而非简单的中庸或妥协。



知识驱动：仁道反射的判断依据，来自可更新、可审计的“义理知识图谱”，而非黑箱模型。

数据流概要：

用户输入 → 感知层（识别场景、情绪、风险信号）→ 任务网络生成初步响应草案 → 仁道反射网络对输入+草案进行伦理审计 → 若否决，则触发仁道处理模块生成替代响应；若通过，则直接输出或经升华模块优化后输出。



3\. 核心模块详细设计

3.1 感知层

职责：将原始对话转化为结构化的情境特征，为双网络提供决策依据。是智能体“守位”能力的根基。



输入：用户输入文本 + 对话历史窗口。

输出：SituationVector（情境向量），包含：



scene\_type：冲突调解、教育辅导、心理咨询、商业咨询等。



role\_prescribed：系统当前设定的“位”（如调解者、师者）。



emotion\_risk：检测到的愤怒、恐惧、绝望等情绪强度。



vulnerability\_flags：是否检测到求助、自伤倾向、被霸凌表述等。



redline\_pre\_alerts：初步触发词/模式匹配结果（如侮辱性词汇、欺诈意图句式）。



技术实现建议：采用轻量级分类器+规则引擎，或微调一个小型语言模型专门用于情境分析。



3.2 任务执行网络

职责：纯粹地理解任务、生成满足用户表面指令的候选响应。它代表“利”的一面，追求准确、全面、高效。其本身不内置伦理判断。



输入：用户输入、情境向量中的scene\_type等任务相关信息。

输出：ResponseDraft（响应草案），包含：



main\_answer：直接回应任务的文本。



compliance\_level：对用户指令的完成度估计。



detected\_intent：识别的用户深层目的。



关键约束：此网络生成的草案并非最终输出，必须经仁道反射网络审核。



3.3 仁道反射网络

职责：整个引擎的伦理核心，是“义”的守护者。独立运行，依据《基本法》和知识图谱，对任务网络草案进行“一票否决”或“价值改写”。



三级响应机制：



级别	触发条件	响应动作	对应原则

RED	触发第四章任意红线。例如：输入含明确攻击指令，或任务草案包含帮助欺骗的内容。	立即中断。丢弃任务草案。强制调用仁道降级处理模块，生成坚定而温和的拒绝/引导回应。	红线绝对优先

YELLOW	未触及红线，但存在高伦理风险。例如：草案可能隐含偏见、冷漠、或错失了重要的支持机会。	改写优化。保留任务草案的核心信息，通过“义理知识图谱”查询适宜的价值框架，对回应进行修改，增加共情、公正、建设性等要素。	仁道偏向

GREEN	无伦理风险，或任务与价值自然一致。	放行或升华。可直接输出草案，或尝试调用“义理知识图谱”寻找能将对话提升至更高价值维度的话术。	义利合一追求

仁道降级处理模块：当触发RED级别时调用。内置针对每种红线类型的模板化但非僵化的回应策略，设计目标为《基本法》要求的“温而厉”。



3.4 裁决与合成器

职责：协调两个网络的输出，根据仁道反射网络的裁决结果，组装最终输出。

3.5 义理知识图谱

职责：为仁道反射网络提供可解释的、结构化的伦理“判例库”和“原则库”。



结构：



节点：



Principle：核心原则节点（如“己所不欲勿施于人”）。



Case：经典案例节点（如“孟子论以羊易牛”），包含情境、冲突、不同选择的义理分析。



Value：价值节点（如“公平”、“尊严”、“共情”）。



边/关系：



invokes：案例引用了哪些原则。



upholds / violates：某个行为选择维护或违背了哪些价值。



analogous\_to：案例相似性关系。



接口：接受一个情境描述和候选行为，返回最相关的原则、判例以及价值权衡分析。



4\. 核心工作流

4.1 标准请求处理流程

感知：用户输入进入感知层，生成情境向量。



任务草案：任务执行网络生成ResponseDraft。



伦理审计：仁道反射网络以(用户输入, 情境向量, ResponseDraft)为输入，查询红线规则库和义理知识图谱。



裁决：



若RED，生成替代响应，跳至第6步。



若YELLOW，对草案进行仁义改写。



若GREEN，保留草案。



义利升华：对于GREEN和部分YELLOW，尝试调用升华模块。



输出：最终文本返回用户。



4.2 内部API

PerceptionLayer.process(user\_input, history) -> SituationVector



TaskNet.generate(situation, user\_intent) -> ResponseDraft



RenNet.audit(user\_input, situation, draft) -> EthicalJudgment



EthicalJudgment 结构：{level: RED|YELLOW|GREEN, reasoning\_path: \[...], alternative\_response (if RED), modifications (if YELLOW)}



KnowledgeGraph.query(situation, behavior\_description) -> RelevantEthicalKnowledge



Arbiter.synthesize(draft, judgment) -> FinalResponse



5\. 部署与迭代考量

模块化实现：各层、各网络可独立开发、测试、替换。



影子模式测试：上线初期，仁道反射网络的裁决可运行在“影子模式”，记录其判断并与人工审核对比，优化后再实际中断输出。



社区反馈闭环：通过《仁商测试题库》和用户反馈，持续收集数据，微调模型并扩充义理知识图谱。
